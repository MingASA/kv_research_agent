# 证据边界与剩余生产决策

**项目当前具备“限定FP8可选能力值得继续工程化”的证据，还没有“所有KV格式/业务都完整支持”或“当前FP8通用默认”的证据。** 模型质量、目标SLO、原生工具流式接口、不同部署规模与维护契约仍决定产品边界。本节把已确定、尚待解释和下一步提案分开，避免把更多实验本身当目标。

## 1. 支持建议与适用范围

| 产品选择/业务 | 当前建议 | 条件与原因 |
| --- | --- | --- |
| 受验证FP8路径作为模型/服务实例显式可选项 | **有条件支持继续工程化** | 限定Qwen2.5-14B/H800/TP1、已测Graph/prefix/调度、fixed scales与后端；展示质量代价，按业务选择 |
| 当前FP8替代所有BF16默认 | **暂不建议** | C128 LB −1.7705pp，长文/多跳/代码有较大任务损失；低压长上下文和工具尾部存在风险，用户未接受损失界 |
| 持续真实聊天压力、吞吐优先 | **FP8有价值候选** | 现代BF16下两次相反臂序仍约+32%RPS/+30%实际TPS；不能用聊天质量直觉替代实际业务质量 |
| 低压长上下文、延迟优先 | **当前观测点优先BF16** | .8796875offeredRPS两臂全成功/吞吐相同，FP8 TTFT/E2E尾延迟更慢；不外推所有低压业务 |
| 明显容量与等待压力 | **保留FP8候选** | 驻留容量真实，中压waiting/TTFT改善；生成期更慢，需按完整E2E与质量/SLO决策，暂无精确峰值容量曲线 |
| 原生工具、流式agent接口 | **保留BF16默认并修复接口** | 完整JSON182/258各自正确但7up7down、FP8一条重复生成；共享streaming parser缺陷另需修复 |
| 质量敏感代码/多跳QA | **先保留BF16，修复候选后重新验证** | LCC/MuSiQue/MultiFieldQA下降；代码相似度与参数匹配都不是执行/多步agent成功 |
| BF16 Q + resident FP8新候选 | **停止本候选额外服务GPU矩阵** | 第46完整1719质量已验收，LB对BF16−2.1491572pp，未观察整体修复；没有新AIPerf，不能沿用原+32% |
| INT8/INT4/V-only/其他模型/GPU/TP/DP | **当前主生产证据不足** | 历史不同实现不可移植；按实际部署价值补候选，避免机械格式/卡数矩阵 |

依据：[现代服务](01_生产服务容量与成本.md)、[质量/工具](02_质量与原生工具任务.md)、[机制/候选](03_算子机制与维护取舍.md)、[第46完整质量与停止决定](06_第46条BF16Q完整质量与停止决定.md)及各表旁原审计链接。这里的“可选”是执行前选择明确配置，不是失败后静默改变已有缓存dtype继续服务。尚无透明跨dtype回退/缓存转换的生产认证。

## 3. 指标与分母统一口径

| 术语 | 本报告定义 | 容易误读的边界 |
| --- | --- | --- |
| resident KV | 实际长期保留的K/V payload+scale存储 | allocator总预留、NVML整卡显存、workspace与实际HBM流量都不同 |
| physical/usable token容量 | pages×128；usable再扣reserved page0 | 不是保证同时执行的sequence数或SLO容量 |
| request RPS | 成功完成请求数/真实observation或trace测量+drain | 过载分母含所有attempts评价成功率；HTTP200不自动等于成功 |
| actual output TPS | 实际输出token总数/同一测量时间 | cap不是实际长度；更多生成可抬高TPS、同时降低请求完成率 |
| TTFT | request-start至first content；offered TTFT从源预定到达开始 | 含客户端/队列/计算；request-start不是服务端arrival |
| 官方 ITL | 每请求content时段与服务端output count形成的平均间隔，再取请求分位 | 不是逐token stall分位；单token不定义，不能填0混入 |
| 完整 offered E2E | 原预定到达至最后raw SSE | 不是官方末非空content延迟，也不是TCP EOF |
| 末SSE完成/token代理 | (first-content→last-raw-SSE)/(server output count−1) | 非硬件decode step、非逐token时间、无语义正确性 |
| 示例合格完成率 | 成功且满足展示用TTFT/平均生成代理阈值的请求数/测量时间 | 阈值未被用户接受、匿名内容无质量，不称正式goodput |
| 任务正确匹配req/s | BFCL官方参数匹配正确数/同一有限cohort observation | 不是执行工具、完整agent成功率或稳态容量 |
| pp | 两个百分比的百分点差 | 与相对变化百分比不同；macro任务等权，不能冒充所有题micro |
| GPU-h | 选用GPU实际占用时长之和，包含失败/加载/JIT/Graph/回收 | 不是仅成功measurement时间，也没有自动货币价格 |

依据：[实际AIPerf计时源码与逐raw核验](../operations/20261026T075846Z/STREAM_TIMING_FINDINGS.md)、[ceff吞吐分母修正](../experiments/ceff-takeover-20261026T040426Z-v2/REPORT.md)、[工具buffered无TTFT](../experiments/production-native-tools-20261027/REPORT.md)。

匿名ignore-EOS请求有时出现末content到末SSE数十秒尾段，原四家族14556条成功测量记录已逐raw核验。极端synthetic尾段最大122819.626ms，完整E2E一直保留；没有导出token IDs，具体EOS/内容/内核原因unverified。官方summary未被改写，新增代理单列；不能靠删尾段制造生成速度。[计时与尾段表](../operations/20261026T075846Z/STREAM_TIMING_FINDINGS.md)

## 4. 样本与因果外推的边界

ShareGPT只有两个同GPU反序paired run、同512measured+16warm来源，观测范围不是总体CI。ToolAgent两个压力点复用同2088source，请求都保留，但跨GPU/时间、每点一对，不给精确压力因果或SLO容量阈值。原过载三家族完成子集不同，成功条件延迟不等于同一批任务纯加速；BurstGPT秒级突发与1秒采样会混叠。[反序限制](../experiments/production-bf16-xqa-sharegpt-replicates-20261027/REPORT.md)、[两压力限制](../experiments/production-bf16-xqa-toolagent-pressure-20261027/REPORT.md)

质量1719是1319道数学+8×50长文/代码原记录，重复C8/C128和候选不会增加独立题数；配对bootstrap以题目为单位，不是GPU重复。BFCL一对258题也是有限cohort；范围探针真正请求只有128，百亿值观测相关。第44新BF16Q算子仅fixture，第46则已用同1719原记录完成模型质量，不增加独立用户。不同prefill、内部Q、writer、kernel和跨run调度仍未单因子隔离，不能由差值直接归因KV dtype或Q。[原质量分析](../operations/20261026T075846Z/production_C128_quality_analysis_b1.json)、[第46对照](../operations/20261026T075846Z/bf16q_full1719_quality_comparison_b1.json)、[范围coverage](../operations/20261026T075846Z/range_probe_c_coverage_and_error_mechanism_v1.json)

## 5. 原因解释的证据强度

| 结论/解释 | 等级 | 为什么 |

| 现代ShareGPT此配置RPS改善约32% | confirmed measurement | 两相反臂序完整raw验收；没有同质量接受或总体CI |

| FA2 FP8-KV prefill值得优先优化 | 有实测支持的工程判断 | 单相同元数据批次attention更慢；多批query/batch不同，不能给全局因果倍数 |
