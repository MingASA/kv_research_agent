# 从手工复制命令转到无人值守的逐步迁移

阶段 0（立刻）：将本包置于 5060 WSL 新控制目录，核对 SSH 主机身份、文件 ownership、项目路径；第一次仅 S0 探查，记录已有 Graph job、排队进程和结果，避免双开。准备 `state/approval.json`（用户实际批准范围，不能自行填默认值）。

阶段 1：5060 Codex 接手 source engineering，本地分支/commit，远端只到用户工作树的全新 worktree；把先前已编译好的 ceff binary 和 v4.2 logs/结果导入 ledger，不重新 build。SSH 心跳与指数退避、tmux 检查、checksum、状态恢复实现为独立可单测的控制器。先用**只读 + 不启动**模式连续检查状态是否稳定。

阶段 2：在明确许可的单 GPU 小预算下，允许现有 runner 的一项固定配对，执行前/后严查 GPU、manifest、hash、真实 Graph replay，失败自动分类且不再重测已成功项。控制端掉线 5 分钟后恢复连接时只恢复观察。验收状态正确后允许无值守的单 GPU 矩阵。

阶段 3：批准更大预算后，按科学信息增益选择 Synthetic 和 Mooncake/质量实验；允许 8 张空闲 H800 并行独立任务但不能夸大 DP/TP；并行必须做全卡稳定空闲和共享资源确认。所有高并发实验要控制服务器 CPU/RAM/SSD 资源，不只看 GPU 显存。

阶段 4：成熟工作流可定期形成报告、提出修复 PR、产出分析及可复现图表，质量下降则分叉新的 scale/attention 研究方向；在不突破安全边界情况下自动开展下一项合理研究，不必每一步问用户。

**危险反例**：直接把旧“过夜队列脚本”作为入口会存在未验证的 `COMPLETE`/concurrency/脚本路径假设，不能原样无检查运行。此包没有刻意制造一个自动开 GPU 的启动按钮，避免高权限账户误操作；实现控制器时必须以 remote ownership/授权为前提。

**v2 补充 — 审批节奏**：阶段 0 用户只需参与一次主机/路径/额度确认，阶段 2/3 若已签发足够的 8 GPU 白名单与累积预算，Agent 不必逐实验、逐 GPU 向用户审批；批准周期结束或需要越界时才请求续期。执行器在真实强制读取预算、持久计量 GPU-hours 与实验去重之前不得自动启动 GPU；从静态模板读取 `enabled:true` 本身并不代表已有安全执行器。
